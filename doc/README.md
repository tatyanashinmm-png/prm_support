# Support Desk

Дашборд для анализа обращений клиентов в Telegram-чатах поддержки. Бот собирает
сообщения из групповых чатов, backend группирует их в обращения, считает SLA и метрики,
ИИ категоризирует обращения и пишет дневные сводки, команда работает в веб-интерфейсе.

## Возможности

- **Сбор обращений из Telegram** — бот слушает группы клиентов; реплаи, категории и
  контекст определяют, к какому обращению относится сообщение.
- **Жизненный цикл** — `Открыто` → `Ожидание ответа клиента` (автоматически после ответа команды,
  SLA в этом статусе не растёт) → `Закрыто`; новое сообщение клиента переоткрывает обращение.
- **SLA в рабочих минутах** (МСК, выходные, праздники); не считается, если задан срок исполнения.
- **Пульс поддержки** — оперативный экран дня: очередь, «новые сообщения», обязательства и их
  просрочки, сводка от ИИ, навигация по дням.
- **Обращения** — таблица с сортировкой, фильтрами, периодом, выбором строк, экспортом в CSV.
- **Панель обращения** — редактирование, платная доработка, обещание клиенту, комментарий, срок и
  Jira, разделение и объединение обращений.
- **Клиенты и аналитика** — карточки клиентов, темы, сравнение периодов; клиенты из Oracle-биллинга.
- **Авторизация и журнал действий** — вход по паролю (и через Google — код готов, не настроен),
  управление пользователями, журнал «кто что менял».
- **ИИ** — Gemini / Groq / OpenRouter по приоритету с откатом на эвристики; приложение работает и без ИИ.

## Быстрый старт (локально)

```bash
cp .env.example .env                 # задайте BOT_SERVICE_KEY: openssl rand -hex 24
docker compose up --build
docker compose exec backend python -m app.seed                            # тестовые данные (необязательно)
docker compose exec backend python -m app.create_admin you@example.com "Ваше Имя"   # первый пользователь
```

- Интерфейс — http://localhost:5173, API — http://localhost:8000 (Swagger — `/docs`).
- Адрес API для фронтенда — `frontend/.env`: `VITE_API_URL=http://localhost:8000` (читается при **сборке**).
- Токен Telegram-бота и список агентов задаются в интерфейсе («Настройки»), не в `.env`.

## Статус

**Готово и работает:** сбор сообщений, обращения и SLA, «Пульс поддержки», «Обращения», клиенты,
аналитика, панель обращения, авторизация по паролю, журнал действий, бэкапы.

**Не сделано:** bot-digest (отправка сводок в Telegram), ролевая модель, Alembic, HTTPS и домен
(нужны для входа через Google), импорт истории чата из выгрузки Telegram.

**Важно знать сейчас** (подробности — в [architecture.md](docs/architecture.md#известные-ограничения-и-риски)):
1. **oracle-sync не работает** с включённой авторизацией — запросы к API идут без токена.
2. `GET /settings` отдаёт браузеру секреты, включая `jwt_secret`.
3. Порт PostgreSQL опубликован наружу с паролем по умолчанию.
4. `POST /ingest/message` открыт без ключа.
