# Бэкапы — два слоя

**Слой 1 — на сервере, каждую ночь, надёжно** (сервер всегда включён).
**Слой 2 — копия на вашем Маке**, на случай полной потери сервера (не
только диска, а вообще всей машины) — автоматизация тут менее надёжна,
ноутбук не всегда включён в момент по расписанию.

## Слой 1. Настройка на сервере (один раз)

```
ssh root@31.58.171.228
cd support-desk-backend
chmod +x backup/backup.sh
```

Проверьте, что скрипт реально работает:
```
./backup/backup.sh
ls -lh backups/
```
Должен появиться файл вида `support_desk_2026-09-21_15-40-00.sql.gz`.

Добавьте в cron — каждую ночь в 03:00:
```
crontab -e
```
строка (проверьте, что путь совпадает с вашим):
```
0 3 * * * /root/support-desk-backend/backup/backup.sh >> /root/support-desk-backend/backup/backup.log 2>&1
```

Хранится последние 14 дампов (~2 недели), старые самоудаляются.

## Слой 2. Настройка на Маке

### Шаг 1 — настроить вход на сервер без пароля

Без этого автоматический скрипт не сможет забрать файлы — уснёт в ожидании
пароля, который некому ввести. Если ещё не делали:
```
ssh-copy-id root@31.58.171.228
```
Введёт пароль последний раз, дальше `ssh`/`scp` на этот сервер будут
работать сами, по ключу.

Проверка:
```
ssh root@31.58.171.228 "echo ok"
```
Если сработало без запроса пароля — готово.

### Шаг 2 — попробовать скрипт вручную

```
chmod +x backup/pull-backups.sh
./backup/pull-backups.sh
```
Должно скачать файлы `.sql.gz` в `~/support-desk-backups/` на вашем Маке.

### Шаг 3 (необязательно) — автоматический запуск раз в день

Честно: раз ноутбук не всегда включён в 09:00 — это best-effort, не
гарантия. Но лучше, чем ничего, и запускается сам, когда Мак включён и
онлайн.

1. Откройте `backup/com.supportdesk.backuppull.plist`, замените
   `ПОДСТАВЬТЕ_ПОЛНЫЙ_ПУТЬ` на реальный путь до проекта (тот же, что
   используете в `cd` каждый раз).
2. Установите:
   ```
   cp backup/com.supportdesk.backuppull.plist ~/Library/LaunchAgents/
   launchctl load ~/Library/LaunchAgents/com.supportdesk.backuppull.plist
   ```
3. Проверить, что запланировано:
   ```
   launchctl list | grep supportdesk
   ```

Если понадобится выключить:
```
launchctl unload ~/Library/LaunchAgents/com.supportdesk.backuppull.plist
```

## Восстановление из бэкапа

```
gunzip -c support_desk_ДАТА.sql.gz | docker compose exec -T db psql -U support -d support_desk
```
(на пустой БД — если восстанавливаете на новый сервер, `docker compose up -d db`
и дождаться Healthy, но backend ещё не поднимать, см. вопрос про миграцию сервера)
