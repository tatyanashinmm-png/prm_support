# Frontend

React 18 + Vite, иконки `lucide-react`, без UI-библиотек и роутера. Собирается в статику и
отдаётся nginx (`frontend/Dockerfile`).

## Структура

| Файл | Содержимое |
|---|---|
| `src/main.jsx` | Точка входа |
| `src/api.js` | Клиент API: `request()` с заголовком `Authorization`, хранение токена (`getToken`/`setToken`), обработчик 401, `normalizeTicket`, `periodParams`, `jiraHref`, объект `api` со всеми методами |
| `src/App.jsx` | **Всё приложение в одном файле** (~4,5 тыс. строк): страницы, общие компоненты, стили (inline), токены дизайна |

Дизайн-токены — объект `C` (цвета), шрифты Manrope / IBM Plex Mono. Светлая B2B-тема,
акцент зелёный.

## Сборка и адрес backend

`VITE_API_URL` читается **на этапе сборки**, а не в рантайме: должен лежать в
`frontend/.env` до `docker compose up --build`. По умолчанию — `http://localhost:8000`.
Смена адреса backend = пересборка фронтенда.

## Вход и сессия

`AppRoot` (экспорт по умолчанию) решает, что показывать:
1. Проверяет токен из `localStorage` (`sd_token`) запросом `GET /auth/me`.
2. Нет токена / 401 → `LoginScreen` (email + пароль; кнопка «Войти через Google» появляется
   только если `GET /auth/config` вернул `google_client_id`).
3. Иначе — основное приложение `App`.

Любой ответ 401 сбрасывает токен и возвращает на экран входа. В сайдбаре — имя пользователя и «Выйти».

## Маршруты

Свой роутер на `history.pushState` (кнопки «назад/вперёд» работают):

| Адрес | Раздел |
|---|---|
| `/pulse` (и `/`) | Пульс поддержки |
| `/clients`, `/clients/{uuid}` | Клиенты, карточка клиента |
| `/feed` | Обращения |
| `/promises` | Обещания |
| `/analytics` | Аналитика |
| `/settings` | Настройки |
| `/audit-log` | Журнал действий |
| `…?ticket={id}` | Открытая панель обращения; ссылку можно копировать |

Известное ограничение: у nginx нет SPA-fallback, прямой заход на `/feed` или обновление такой
страницы может отдавать 404 (см. [architecture.md](architecture.md#известные-ограничения-и-риски)).

## Разделы

### Пульс поддержки
Оперативный экран дня.
- **Шапка:** навигация по дням (‹ дата ›, клик по дате — календарь; вперёд дальше сегодня
  нельзя), «Обновлено N назад», переключатель «ИИ-ассистент» (`localStorage`, только для
  этой страницы).
- **Сводка от ИИ** (если ИИ включён и настроен): свёрнута до строки, «Развернуть»,
  «Перегенерировать», «Отправить в чат» (только за сегодня; сейчас заглушка).
- **Метрики.** «Требуют внимания»: открыто сейчас, с прошлых дней, просрочено обязательств
  (красным). «Итоги дня»: обращений всего и активных чатов (со стрелкой к вчера), закрыто,
  среднее время ответа. Плитки «Открыто сейчас», «С прошлых дней» и «Закрыто» кликабельны — переключают вкладку очереди.
- **Очередь** — вкладки Все / Открытые / С прошлых дней / Ждут клиента / Закрытые со счётчиками.
  Фильтры: поиск, VIP, «Есть новые сообщения», категория, тариф, статус подписки, клиент
  (в списке только клиенты, чьи обращения есть на экране).
  Группы: **С прошлых дней — разобрать в первую очередь** → **Открыто сегодня — по времени
  ожидания** → **Ждут ответа клиента** (на «Все» свёрнута) → **Закрытые** (по дате закрытия).
  Группы сворачиваются кликом по заголовку; «Ждут ответа клиента» на вкладке «Все» свёрнута по умолчанию.
  Внутри групп сначала обращения без ответа, потом по убыванию времени ожидания.
- **Карточка обращения:** значки VIP и ₽ (платная доработка, подсказка при наведении),
  чип «● N новых» (клик — «прочитано»), справа «создано …» и состояние ответа:
  «без ответа · X» (янтарный до часа, красный дольше), «ждёт X», «1-й ответ за X»;
  кнопка «Закрыть» с тостом «Отменить» на 6 секунд. Клик по строке открывает панель.
- **Справа:** «Просроченные обязательства» (красная рамка, на сколько дней просрочено, Jira),
  «Ближайшие обязательства · 3 дня», «Обязательства» (срок + Jira, не просроченные).
- Обращения со сроком исполнения показываются **только** в блоках обязательств и не
  дублируются в очереди.

### Обращения
Таблица всех обращений.
- Вкладки: Все / Открытые / Нарушен SLA / Ждут клиента / **Задачи со сроком** (не закрытые
  со сроком) / Закрытые; красная плашка «N превысили SLA — Показать».
- Фильтры: поиск (тема, клиент, SUP-код, Jira), **период** (кнопка «Период: 30 дней ▾»:
  Сегодня, Вчера, 7/30/90 дней, Всё время, Произвольный), категория (с поиском и счётчиками),
  VIP, «Платная доработка», «Сбросить».
- Колонки с сортировкой: Тикет, Тема, Клиент, Категория, Создано, Ожидание, **Срок**, Статус;
  плюс Jira. Обращения без срока при сортировке по сроку всегда внизу.
  У обращений со сроком вместо времени ожидания — «SLA не считается».
- Выбор строк чекбоксами, «Экспорт выбранных»; экспорт из меню в шапке — по текущим фильтрам
  или все обращения. Формат **CSV** (разделитель `;`, с BOM — Excel открывает кириллицу).
  Колонки: тикет, тема, комментарий, обещание клиенту, срок, клиент, категория, создано,
  ожидание (мин), статус, **полная ссылка на Jira**, платная доработка.
- Пагинация 10/25/50.
- **«Создать обращение»** — боковая панель: клиент (автодополнение), категория, наименование,
  комментарий, статус, срок исполнения, Jira (ключ или URL). `⌘/Ctrl+Enter` — создать.

### Панель обращения (боковая)
Открывается по клику на любое обращение в любом разделе.
- Шапка: номер (клик копирует), статус, меню «⋯» (Разделить, Объединить с тикетом клиента,
  Скопировать ссылку, Удалить с подтверждением), закрытие; клиент, тариф, дата.
- Поля: наименование (растёт по высоте под текст), категория (поиск, добавление, переименование
  для всех тикетов), платная доработка (плановая/фактическая стоимость, часы, расхождение),
  переписка, обещание клиенту (быстрые фразы), **комментарий**, срок, задача в Jira.
- SLA-шкала; при заданном сроке — «SLA не считается».
- **Режим разделения:** зелёная плашка с тремя шагами, выбор сообщений кликом по карточке,
  `Shift`+клик — диапазон, «Выбрать все»/«Снять выбор»; форма нового тикета закреплена снизу
  (тема из первого сообщения, категория, «Перенести/Копировать»). После создания — тост со
  ссылкой «Открыть».
- **Объединение:** закреплённая нижняя область с выбором целевого тикета.
- Открытие панели автоматически отмечает обращение «прочитанным».
- Длинные токены и ссылки в сообщениях переносятся; переводы строк сохраняются.
- **Сайдбары закрываются только осознанно:** крестиком или «Отмена», не кликом по фону и не `Esc`.

### Клиенты и карточка клиента
Таблица клиентов с метриками за 30 дней, фильтры (поиск, чипы «Есть открытые / Просрочены /
Риск / VIP», тариф, статус подписки — по умолчанию только активные; клиенты без статуса не
скрываются), добавление и удаление клиента. Карточка: период, метрики, темы по месяцам,
история обращений с фильтром по статусу, правка названия чата и VIP по клику, название
чата из Telegram.

### Обещания
Обещания по срокам: просроченные / сегодня / ближайшие / выполненные. «Выполнено» очищает срок.

### Аналитика
Сравнение выбранного периода с предыдущим такой же длины: итоги, новые/активные/ушедшие клиенты,
дельты по клиентам и категориям.

### Настройки
Карточки: «Мой аккаунт» (смена пароля), «Пользователи», «Вход через Google», провайдеры ИИ
(порядок = приоритет), токен бота и список агентов (с поиском участников переписки и
пересчётом ролей), пороги SLA и рабочие часы/дни/праздники, Jira base URL, синхронизация
Oracle (SQL, кнопка запуска), сводка, промпты.

### Журнал действий
Таблица «когда / кто / действие / детали», фильтр по типу действия, пагинация по 50.

## Как обновляются данные

Общий счётчик `refreshTick` в `App` увеличивается после любого изменения
(`onDataChanged`); разделы подписаны на него и перезагружают свои данные.
Чтобы экран не мигал, «тихие» обновления не сбрасывают состояние в `null`: у
`ClientDetailPage` и `AnalyticsPage` есть ключ контекста (клиент+период) — экран загрузки
показывается только при смене контекста, при фоновом обновлении данные подменяются на месте.

## Выпадающие списки и оверлеи

`StyledSelect`, `CategorySelect`, панель периода и подсказка значка ₽ рисуются через
`createPortal` в `<body>` (позиция `fixed`) — иначе их обрезают родители с `overflow`.
Общий `MultiSelect` (с чекбоксами и опциональным поиском) рисуется обычным `absolute`.
